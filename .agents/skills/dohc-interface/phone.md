# The phone app

The phone app (`apps/mobile`) follows the rest of this skill, except for the differences listed here.
The phone does each difference on purpose.
Before you add or change a difference, follow [`apps/mobile/AGENTS.md`](../../../apps/mobile/AGENTS.md#platform-differences).

## Platform

- Touch targets are at least 44 pt.
- Use the system's tab bar, navigation, large titles, sheets, and haptics on iOS, and Material's on Android.
- Body text is 17 pt, with Dynamic Type. The system font is a listed difference.
- Use SF Symbols only where iOS draws the control. Use lucide for dohc's own content.
- A confirmation is an action sheet or a system alert, with the desktop's words. Delete, Forget, Leave, and Remove use the destructive style, including in a long-press menu.
- Every swipe and long-press has a visible control that does the same thing.
- Toasts sit at the bottom, in 16 pt gutters above the tab bar or the composer, on a solid surface, with a visible ×.
- The composer docks to the keyboard.
- There are no tooltips.

## Surfaces

1. **Clamps.** Toast titles take 4 lines and Notices row titles 3, where the desktop takes 2. A tap opens the rest in place, as the desktop's click or Show more does.
2. **Notices rows and VoiceOver.** A row is one element. Its actions are in the rotor in this order: the worded action (Open, Open note, Reply, Answer, or Try again), Try again when a mention's or question's message couldn't be read (#17), Try again when its answer's agent states couldn't be read (#18), Mark read or Mark unread, Copy, then Done, or Dismiss on a failure held on this phone. A pill and its rotor action share one handler. The spoken time is in full ("2 minutes ago"); on screen it is the desktop's ("2m ago"). A row whose answer is open, or that holds an answer of this phone's that isn't saved (#17), is a group instead: VoiceOver reaches its text, the question, each choice, the field, Send, Cancel reply, Open, the marks, Copy, and Send or Discard on its answer one by one, because a rotor can't hold a text field or a poll's choices. Closing the answer puts VoiceOver back on the row.
3. **Header.** Mark all read is a system bar button. The header glass is the system's, themed by the navigation theme.
4. **Done** ends editing, and shows only while the keyboard is up. It only dismisses the keyboard. On a Notice from the server, Done is the Notice's own action (#17), on a list with no keyboard, and a row whose answer is open, or that holds an answer of this phone's that isn't saved, has none.
5. **Properties** are read-only for now, with nothing that looks editable: no field outlines, and a chevron only on a value that opens something.
6. **The state mark** opens its explanation on tap. VoiceOver hears the mark's label with the explanation as its value.
7. **Lossy and large files** have no Open externally. The large-file strip says to open it on a computer. A large file's state mark reads Read-only, as every read-only page's does, and its explanation says the file is too large to edit.
8. **No device-file states.** The phone saves to the server, so it has no Saved to host, Saved locally · Pending share, File in use, Changed outside dohc, Reloaded, or Replaced. Deleted keeps the last text, read-only, and does not mention the trash.
9. **Page and chat buttons.** A page's header has "Chat about <file>", and a file chat's header has "Open <file>".
10. **Computer-only**, with no disabled entry on the phone: Collection delete, Versions, and in Sharing the conflicts banner, skipped changes, Copy code, and the waiting-changes review.
11. **A page that fails to load** (its view, or the editor files it needs) shows "dohc could not open this file." with Try again. If the editor files could not be written for lack of space, a second line says "Not enough storage on this phone. Free up space, then choose Try again." The could-not-open strip is only for text shown read-only because editing could not start. A page that's gone offers no Try again.
12. **End share names the file.** The phone's alert asks "End the share of <file>?", where the desktop asks "End this share?" beside its row. With changes waiting, it asks "End the share of <file> and decline <N> changes <who> sent?".
13. **A failed End share's toast** has a 2-line title, not 4. It cuts the file's name and each person's in the middle to fit. Its Notices row and Copy keep the whole text.
14. **Sign out**, where the desktop says Disconnect. The desktop's Disconnect stops sync and keeps the files on the computer. The phone keeps no work of its own except messages in its outbox, so it only signs out. Its sheet counts the messages it deletes: "2 messages haven't been sent. Signing out deletes them." and "1 message may still send." When the phone can't read its outbox, it says "dohc could not check this phone for unsent messages. Signing out deletes any it has." If it can't delete them, it stays signed in and shows "dohc could not delete the messages waiting on this phone, so it didn't sign out." with Try again in place, and the composer says "dohc could not delete the messages waiting on this phone. Try again in Settings." If the server has already ended the session, Connect shows the failure above its form or code instead, with Try again: "dohc could not delete the messages waiting on this phone. They may send if you close dohc and sign in again." Only memory holds a failed delete, so a relaunch forgets it. Try again signs out again, and deletes the messages of every account whose Sign out failed, even if another sign-in finished meanwhile. Until a Sign out finishes, Connect server can't be chosen, and Connect stays on screen even if a sign-in already under way finishes.
15. **Settings** opens from your mark at the right of the Chats header, as in Slack. It holds the account and its server, Show on phone for each workspace, the account's sessions with End session, and its agents with Sign out, Remove and Restore. The desktop has no session or agent list yet.
16. **Connect, Settings, a chat and a page show their errors in place**, with Try again, and file no toast or Notices row. They sit outside the tabs, where toasts show. A failed refresh keeps what's shown, with the cause and Try again above it.
17. **Notices in a signed-in build** list the account's Notices that the server shows phones, with failures held on this phone, such as a read of Home or Chats, on top.
    - A row stays unread until the person opens it, marks it read, or presses Mark all read. The phone has no pointer or focus to read a row by reaching it, so a Notice from the server shows Mark read or Mark unread under its text. Swiping right marks a read Notice unread; an unread one has no swipe right.
    - A Notice from the server has Done where a failure has ×: a check in a circle, and swiping left. Done takes it off the list everywhere the account reads Notices. Its toast says "Marked done" with Undo, shows on Notices too, and stays until closed, because it holds the only Undo. A later Done's toast replaces it. A failure held on this phone keeps Dismiss.
    - Read, unread, Done and Undo work on every row the phone shows. Open, Reply and Answer work only in an owned workspace that shows on the phone.
    - With phone writes on, a mention's row has Reply where Open was, once the phone reads the mention's thread and the read shows the exact message the Notice names. Reply reads the row, opens the workspace and the thread at that message, with it chosen to reply to, as a message's Reply chooses it (#18). The phone reads only the mentions on screen, one read per thread, and checks the list and the read again when Reply is pressed. Until a read shows the message, and for every other Notice, the row keeps Open. A read that fails keeps Open and adds "dohc could not read this message." with Try again, in the row, with no toast or Notices row of its own. The desktop has no Reply on a Notice.
    - With phone writes on, an agent-run Notice's row has Answer where Open was, once the phone reads its thread and the read shows the exact message the Notice names as an agent's open question or poll, and a fresh read of the workspace's chat list says whether the thread is a post's. Neither the Notice's words, its sender, nor an agent's name makes a message a question. Answer reads the row and opens the answer in the row, without opening the workspace: the whole question, its author's name, a poll's choices, which answer at a tap, or the field named "Answer <name>", with Send and Cancel reply, and Open. The name is the question's author's, which can differ from the Notice's sender. The answer goes through the outbox to the Notice's own workspace, where the desktop puts it, as a thread's answer does (#18). While the answer is open, or the row holds an answer of this phone's that isn't saved, the row has no Done and no swipe. A poll's answer closes once the outbox keeps the choice. A typed answer closes once its field has cleared the text sent; text typed meanwhile stays, with Send off, since the question has its answer. The row then says Answering, then Answered or Already answered, as the card does. Every answer this phone keeps that isn't saved shows in its row, as in its thread: Discard while it waits or sends, Send and Discard when withheld, Copy message and Discard when refused or still sending. It stays after its workspace stops showing on the phone, without Send. The field's text stays while its row scrolls away and back, and through a failed read, with Send off until a read shows the question again. Cancel reply, leaving Notices, the Notice leaving the list, its workspace hiding, and a sign-in change close the answer, and the text goes. The desktop has no Answer on a Notice.
    - An automation wake, which the server doesn't show phones, would have no swipe and no Done.
    - Open goes to a thread at its message, or a page, in the Notice's workspace when it shows on the phone, and opens that workspace. A row the phone can't open says "Open on your computer" after its time. Opening reads the row and never runs anything.
    - A failed read of the list, or marks that can't be sent, is a toast and a row with Try again. Marks wait on the phone, a relaunch included, and send in order when the server answers.
    A change feed that fails 3 times in a row shows as a failed read does, so content never goes out of date without a sign: a toast and a row on the tabs, and a line above a chat or page. Try again starts the feed at once, and its next answer takes the failure back.
18. **Reading only, in a signed-in build, until phone writes turn on.** Phone writes are off by default (`apps/mobile/src/server/phoneWrites.ts`). While they're off, the phone sends the server nothing but read marks and Notice marks, and a chat has no composer. A sample build always shows the composer, over an outbox in memory that reaches no server.
    - With phone writes on, a chat's stream has the composer, docked to the keyboard, with Send. A Group that takes posts adds New post, with an optional title. A thread's composer replies, at the top of the thread.
    - A message the server has, and a post or message waiting on the phone, has a visible Reply. The phone has no reply gesture, on a message or on a Notice. In a thread, Reply names the message above the field ("Reply to <name>", with Cancel reply), and the reply goes under it. In a chat, Reply on a message opens its thread to reply there, and on a post or message still on the phone it replies in place, and the reply waits for that message's thread. A Notice's Reply opens the thread the same way (#17). If the chosen message is gone when the thread's read answers, the context says "Reply", with Cancel reply, and Send stays off, so the text never goes to the thread's top.
    - A message that asks a question or a poll shows Unanswered or Answered, as on the desktop. A poll's choices are buttons in its author's own words, and a tap answers at once. A question without choices has Answer, which opens its thread with the field named "Answer <name>". An agent's question a Notice names also takes its answer in the Notice's row (#17). The answer is a reply, where the desktop puts it, through the outbox. The phone's answer can wait, so the phone adds words the desktop doesn't need: the card says "Answering" until the outbox saves the answer, and then the server's state wins. When the server took another answer first, the card says "Already answered" with the winning answer if a read shows it, or only Answered, naming nobody. "Sent your reply. Another answer was chosen." shows only once a read shows the phone's reply. A withheld answer is its reply's row, with Send and Discard, and a refused one has Copy message and Discard. An answered question takes no answer.
    - A message the server has shows its reactions as buttons, with Add reaction, which opens the desktop's choices under it and returns focus to Add reaction when it closes. A tap asks for the state the reaction should end in, never a toggle. A reaction the phone hasn't settled has a dashed border, and the message takes no other reaction until it settles. A withheld reaction says so, with Send and Discard. A refused one shows the server's state again, says so, and offers Discard.
    - A message waits in the outbox and shows in the chat until a read shows it: "Waiting to send", "Sending", then "Still sending" after 10 minutes of pending answers. A message the phone kept withheld says "This message has not been sent." with Send and Discard. When its storage may still hold it ready to send, because a change that would have let it send, or a failed Discard, couldn't be confirmed, it adds "It may send if you close dohc and open it again." A reaction says the same after "Your 👍 reaction has not been sent." One still sending, or refused, has Copy message and Discard. Discard asks first, and says "It may still send." when a request may have reached the server.
    - A message the server has shows a line for each agent it woke, under its text, with the agent's current name, or "An agent" when no computer names it now: "Nova is waiting for a computer", "Nova is starting on <computer>", "Nova didn't start", or "Nova isn't confirmed on <computer>. It may have started.", with "a computer" when none is named. An ended one adds "No other computer can run this agent." when that's so. A wake waiting to send, or queued on a computer, has no line. Two wakes with one name keep two lines. With phone writes on, a line that didn't start has Try again, and one that isn't confirmed has Try on another computer, which first warns "If <computer> already started <name>, it may run twice." Either sends once, while the chat is on screen, and the line shows the next read; a failure keeps the line, adds "dohc could not retry this agent." and Try again. The lines follow the server while the chat is on screen. A failed read keeps them, adds "dohc could not read this agent's state." and Try again. An agent-run Notice's row shows the same lines for the answer a read shows chosen, never a reply of this phone's that lost.
    - Text the outbox couldn't keep stays in the field, with "dohc could not keep this message on your phone." and Try again above it. Each failure stays in place, with no toast or Notices row.
    - Settings links to Messages on this phone, which lists every message waiting for the account, in any workspace, and records that can't be read.
    - When the file that keeps the waiting messages is damaged, nothing replaces it on its own. The composer says "The file that keeps messages waiting on this phone is damaged. Delete it in Settings, under Messages on this phone." Messages on this phone says the file is damaged and offers Delete, which asks first: "Delete messages waiting on this phone?", "Messages that haven't been sent will be lost. Messages the server has stay in their chats.", and Delete messages. A failed delete says "dohc could not delete the damaged file." with Try again in place. Sign out deletes the damaged file too, after its sheet's warning that it could not check for unsent messages.

    A page is read-only, with the Read-only mark, unless phone writes are on (#23). Chats lists groups, people and agents, with no file chats: the server gives the phone none yet. Unread follows the account's read marks, as on the desktop: an unread chat's name is bold, and a person or an agent shows its count. While a chat or thread is on screen, its conversation is read up to the newest message shown, and an unread post up to its own message, as on the desktop. Home lists Pages, Other files, Apps (#22) and Collections (#24).
19. **The workspace switcher** lists every workspace that shows on the phone. One whose sync isn't set up yet is dimmed, says "Not synced yet", and can't be chosen. Its Show on phone switch in Settings stays as it is.
20. **A page the server won't send.** A file over the editor's limit says "This file is too large to open on a phone. Open it on a computer.", because the server sends none of it. A page whose workspace is being restored says "This page is being restored." with Try again.
21. **Scan code** sits beside Connect's server address, because typing an address on a phone is slow. It reads the QR code a computer shows under Connect a phone, which holds only its server's origin. A valid code fills the address and closes the scanner, and the person then chooses Connect server, as after typing it. A scan never opens a sign-in page by itself, so a swapped code can't pick the server for them. Any other code says so in the scanner, which keeps scanning. The phone asks for the camera at the tap, never at launch.
22. **Apps.** Home's Apps lists the open workspace's published apps over one transactional Collection or over nothing in the workspace, the only ones the server serves phones yet. Each version sits under its app's name as "Version <first 7 characters of its source revision>"; an app with one version shows it beside the name. A version opens its review: its version and publication date, its publisher, what it can reach, or "Nothing in this workspace.", that it can send what it reads, and what you enter in it, to other websites, and its declared source as plain text, or "This version's source isn't available." The desktop approves an app on one device; the phone's approval holds for that exact version on every phone of the account, so the review says "Approved on your phones". Approve and Open show only while phone writes are on, since a running app can change its Collection, and Open only on an iPhone, where the runner's rules hold. Elsewhere the review says "This app can't be opened on this phone yet." Revoke shows on every phone, with an alert, since an approval made on another phone needs its way back here. A failed Approve, Open or Revoke shows in place, and Try again repeats it. Open runs the app full screen in a WebView of its own, with the native Back button and no swipe back. Leaving the review while it opens cancels it. Sign out, another sign-in, a workspace switch, Show on phone off and Revoke close the app at once. A revoke on another phone or a withdrawn publication closes it at the next read of the workspace's apps, every 15 seconds while it runs and on each return to the foreground; the server has already ended its access. A tapped link opens only over HTTPS, never on the dohc server or the app domain, and only after the alert "Open in Safari?" naming its host.
23. **Editing a page on the server.** With phone writes on, a page shows the text read, read-only with Opening…, until the server opens it live; then it takes edits. The mark stays quiet: Saved, which only the server's host applying every edit made here gives, and Saving draw nothing, and their label and explanation say which. A lost connection stops editing, puts the keyboard away, and shows Read-only with "dohc could not reach the server." and Try again under the header. A page the server won't open stays read-only with its reason; one no computer has opened live says "Open this page on a computer once to edit it here." Edits the server hasn't applied live only in the page's memory: Copy as Markdown always copies them, and leaving the page asks first, with Copy as Markdown and Discard edits. Sign out, another sign-in, a workspace switch and Show on phone off close the page's connection at once. The desktop saves to disk, so it has none of these.
24. **Collections, read-only.** Home's Collections, under Apps, lists the open workspace's transactional Collections by name, and shows only when there is one. A Collection opens to its first table's records in a list, 50 at a time, with the next 50 read as the list nears its end; a Collection with more than one table has a button for each above the list. Each row shows the field that names the record, then up to two more fields with a value, a checked checkbox by its field's name. Pulling down, and a return to the foreground, read the Collection again; the feed doesn't report record changes yet. A record opens to every field's name and value: a checkbox's mark, a date in the phone's locale, choices joined by commas, a web address as a link that asks "Open in Safari?" (#22), a relation as its records' IDs, and an attachment as its file's name, or "Attached file" when the server has none. Button fields don't show. A table nothing reads says "Nothing in this Collection reads <table>'s records." Nothing changes data: the phone has no edit, add, delete, Undo or button, and no table, board, search, filter or sort, which the desktop has. Document Collections don't show yet. Records stay in memory only, and Sign out, another sign-in, a workspace switch and Show on phone off drop them at once.

Browser alerts gain the message text after phone push lands.
